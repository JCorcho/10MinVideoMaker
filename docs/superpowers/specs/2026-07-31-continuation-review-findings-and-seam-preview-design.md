# Continuation Review Findings and Assembled Seam Preview Design

## Goal

Preserve the two unexpected LTX 2.3 style-conversion discoveries, record the
owner's human acceptance findings, and add a production-faithful assembled
seam preview without changing continuation generation or approving automatic
rollout.

## Acceptance decision

Acceptance run `continuation-acceptance-20260731-065935` does not approve any
method for production continuation:

- `single_frame` is the only method that preserves the source's cel-shaded
  style, face, hair, wardrobe, and proportions. It restarts with a
  near-duplicate conditioning frame, then loses fine eye detail and develops
  strong motion blur. It remains the next production baseline, not an approved
  rollout.
- `decoded_17_frame` preserves motion direction, background, wardrobe geometry,
  proportions, and stable anatomy, but changes the subject from cel-shaded
  anime/game rendering to photoreal live action. It is rejected for production
  continuation and preserved as a high-value anime-to-live-action experiment.
- `latent_overlap` preserves a plausible temporal transition and improves hand
  anatomy, but changes the source into semi-realistic 3D, changes hair into a
  head-covering-like shape, and reduces forward walking into robotic body
  motion. It is rejected for production continuation and preserved as a
  secondary anime-to-semi-realistic experiment.

The automatic continuation gate remains locked. This work must not create or
edit `continuation-validation-v1.json`.

## Evidence and interpretation

The human findings agree with the existing mechanical metrics:

- `single_frame` has low boundary RGB MAE (`3.626852`) but the highest measured
  motion-vector discontinuity (`6.833459`).
- `decoded_17_frame` has severe guide-end RGB MAE (`56.684467`) and motion
  discontinuity (`4.773929`).
- `latent_overlap` has severe guide-end RGB MAE (`29.171497`) but the lowest
  motion discontinuity (`1.702146`).

These values prove that low optical-flow discontinuity cannot establish visual
identity or style continuity. Human review remains authoritative.

`single_frame` continuation frame 0 is a reconstructed conditioning anchor, not
the first new timeline frame. It is visually near-identical to base frame 120
but not byte-identical. A production-faithful join retains base frame 120,
drops continuation frame 0, and begins new motion at continuation frame 1.

The decoded diagnostic uses base frames 96 through 112 as its 17-frame guide.
Its production-faithful diagnostic join therefore ends the base at frame 112
and begins the continuation at frame 17. The latent-overlap method retains the
full base through frame 120 and begins new continuation motion at frame 25.

## Assembled seam preview

Keep the existing side-by-side videos, exact-seam stills, and seam-seek button.
Add a third video card titled **Assembled seam preview** below them.

For each selected method, the server creates a browser-safe, unwatermarked,
CPU-encoded H.264 MP4 on first request:

- `single_frame`: base frames `0..120`, then continuation frames `1..end`;
- `decoded_17_frame`: base frames `0..112`, then continuation frames `17..end`;
- `latent_overlap`: base frames `0..120`, then continuation frames `25..end`.

The preview is a visual diagnostic only. It omits audio to avoid masking visual
seam judgment and to keep filter behavior deterministic. The UI displays the
exact retained and dropped frame ranges beside the player.

Preview files live only at:

`D:\LTX_Supervisor_Storage\acceptance\<run-id>\review\assembled-<case>.mp4`

FFmpeg writes a same-directory temporary file, verifies a non-empty result,
then atomically replaces the target. Existing non-empty previews are reused.
Raw FFV1/FLAC media remains untouched.

## API and security

Add:

`GET /api/acceptance-runs/{run_id}/assembled/{case_name}`

The route uses the same run-ID, case-name, storage-boundary, artifact-existence,
LAN Basic authentication, 404, and FFmpeg-503 behavior as the existing review
media routes. No arbitrary paths are accepted.

The review document adds, per case:

- `assembled_video_url`;
- `assembly.base_end_frame`;
- `assembly.continuation_start_frame`;
- `assembly.dropped_continuation_frames`;
- a human-readable assembly summary.

No route may queue ComfyUI, start the supervisor, poll Gmail, change job state,
or approve rollout.

## Tests and verification

Use test-driven development:

1. Service test verifies exact FFmpeg trim/concat filters, atomic output,

2. Service test rejects unknown cases and failed FFmpeg output.
3. GUI route test verifies MP4 delivery and LAN authentication.
4. Static UI test verifies current comparison views remain and the assembled
   player is present, native-video capable, and mobile responsive.
5. Preservation tests verify frozen workflow files and manifest hashes exist
   and contain no known secret markers.

Run focused tests, all unit tests, syntax compilation, and `git diff --check`.
